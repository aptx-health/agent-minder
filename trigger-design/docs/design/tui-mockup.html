Trigger · TUI design · mockup

Does anything need me,
and can I act on it right here?

The terminal interface for Trigger — a local daemon that runs scheduled and triggered agent workflows. An attention-routing surface, not a dashboard: parked runs are the headline, the live log stream stays home, and every action is one keystroke away.

Direction: persistent panels + overlay Base: bubbletea v2 / lipgloss Spec: tui-mockups.md Date: 2026-08-29

02

State reads at a glance

Each run state maps to a glyph + colour + card weight, so status never depends on colour alone. Semantic hues are separate from the violet accent.

■ awaiting_input

Agent paused to ask a question or request scope. Loud, top of strip.

✗ blocked / failed

A failure needs diagnosis. Loud, with the failing step named.

◐ running

In flight. Animated glyph; live step line renders dim/italic.

✓ succeeded

Done. Quiet — a durable transition in the stream, not an alert.

▸ focus / selection

The violet accent marks focus and the checkout class only.

03

Answer in place — the parked-run overlays

Press enter on a parked run and a floating card takes over. Three shapes share one release path; the runtime session resumes without a restart.

04

Drill into a run — steps as the spine

Press enter on a stream line (k9s-style drill-down). Steps are deterministic facts; the log tail is live. Behavioural scenarios slot in here later as sub-rows going red→green.

05

Why it's built this way

The interaction and disclosure model, harvested from the current TUI wave.

Keyboard model

↑↓ / jkmove
enteranswer (strip) / drill in (stream)
tabswitch panel — footer keys follow focus
ccheckout / actions menu
l / Ltail log / open raw log
pjump to PR
f / xfire job / cancel run
g / :go-to :run N, :job name

Default vs. on demand

  • Default: the headline count, the parked runs, and the live stream. The answer to “does anything need me?”
  • One key deeper: full request payload, schema, evidence, and the answer overlay.
  • Drill-in: the step list, per-step timing, provenance, worktree + PR.
  • Never shown: secrets — summary/data are secret-free at the source.
  • Live-only: progress telemetry renders dim/italic and is never promoted to history.

Crash-safe by construction

  • The header shows the (epoch, id) cursor and a live dot.
  • Reconnect resumes from the cursor; on epoch mismatch the client resyncs and shows a ⟳ resynced toast rather than drifting.
  • The TUI is a thin client — never the source of truth, never blocks the daemon.
06

Design provenance

This direction harvests the 2026 TUI wave rather than inventing from scratch.

hyperb1iss/hyperskills · tui-design

The ranked pattern / anti-pattern library these foundations follow — semantic colour tokens, three-tier disclosure, spatial consistency.

lazygit / lazydocker

Persistent multi-panel with single-letter actions. Source of the rule that panels never move.

k9s

Drill-down stack (list → detail → log) with : jumps — the run-detail navigation.

btop

Unicode block glyphs and semantic status symbols (● ○ ◐) for state at a glance.

Bubble Tea v2 (Feb 2026)

Mode-2026 synchronized output removes tearing on a scrolling stream — the stable base for the live view.

Charm Lipgloss

Semantic style tokens, layered surfaces, rounded borders — the modern-maximal look, degrading to 16-colour.

“TUI Renaissance 2026” writeups

Design-in-layers, keyboard-first / mouse-optional, async-everything, evidence over conclusions.

Mockup — not shipping UI. Screens rendered as HTML/CSS to preview the true-colour target (Ghostty-class terminal); the real build is bubbletea/lipgloss and degrades to 16 colours. Full spec: trigger-design/docs/design/tui-mockups.md.
