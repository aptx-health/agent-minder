## [Unreleased]

### Fixed
- **Eventbus log bounded; lag past retention is loud and recoverable**: The in-memory event log grew without bound in a process that is explicitly long-lived, and an abandoned subscription (reader gone, `Close` never called) parked its delivery goroutine forever on a full channel. The log now retains at most a fixed number of events (`DefaultMaxRetainedEvents` = 4096; tunable via new `NewWithRetention`), with cursors staying monotonic across truncation. `Subscribe`/`Replay` below the retention floor return a typed `ErrTruncated`, and when retention passes a lagging subscription's unread events the bus terminates it with the same error — its `Events()` channel closes, new `Subscription.Err()` reports `ErrTruncated`, and the documented recovery is snapshot-then-resubscribe. That termination is also what reaps abandoned subscriptions' goroutines. Other subscribers are unaffected, and the never-silently-drop invariant is preserved: loss is always signalled, never skipped over. Foreground output is unchanged. (#606)
- **Daemon API key compared in constant time**: The HTTP API auth middleware compared the caller-supplied `X-API-Key` header against the configured key with `!=`, whose byte-by-byte short-circuit leaks how many leading bytes of a guess are correct (CWE-208), letting a LAN attacker recover the key by timing. The comparison now runs through `constantTimeEqual`, which SHA-256-hashes both sides and compares the fixed-size digests with `crypto/subtle.ConstantTimeCompare` — constant-time and length-independent. No behavior change for valid callers. (#599)
- **Windows support documentation now matches verified behavior**: README platform support now documents WSL2 as the supported Windows path, native Windows as limited because daemon/reaper process APIs are Unix-only, clipboard behavior through `github.com/atotto/clipboard`, CGo-free SQLite via `modernc.org/sqlite`, and Bubble Tea's dependency-level Windows console support. `GH_TOKEN` is now accepted as a fallback after `GITHUB_TOKEN` and normalized into `GITHUB_TOKEN` for subprocesses. (#223)
- **Schedules scoped to their deployment; last-run preserved across reconciliation**: `job_schedules` was keyed by `name` alone, so two deployments sharing a schedule name collided and a re-sync could discard `last_run_at`. Schema migration v8→v9 rescopes the primary key to `(deployment_id, name)`, preserving all existing rows and their last-run history. `UpsertSchedule` now uses `ON CONFLICT(deployment_id, name) DO UPDATE`, refreshing the definition columns while leaving `last_run_at`/`created_at` untouched, and `GetSchedule`/`UpdateScheduleRun`/`DeleteSchedule` are scoped to `(deployment_id, name)`. (#570)
- **Removed automations are disabled during reconciliation**: `Scheduler.SyncSchedules` now disables any persisted `job_schedules` row for the deployment whose definition no longer exists in `jobs.yaml`, so a deleted job stops firing instead of being left enabled/orphaned. New `db.SetScheduleEnabled` store method scopes the toggle to `(deployment_id, name)`. (#568)
- **Trigger budget/turn overrides now reach activated jobs**: A `jobs.yaml` trigger declaring `budget` or `max_turns` had those overrides silently dropped at activation because `TriggerRoute` never carried them. `TriggerRoute` now carries `Budget`/`MaxTurns`, `createJobForIssue` writes them onto the job, and `CreateJob` persists the `max_turns`/`max_budget_usd` columns so the effective limits are truthful. No schema change. (#567)
- **`milestone:*` triggers now install as active automations**: A `jobs.yaml` trigger of the form `milestone:v2` previously validated but was dropped during trigger-route construction (`triggerRoutesFromConfig` only handled label triggers), so it silently did nothing. Milestone triggers now become active trigger routes matched on the milestone: `TriggerRoute` carries a `Milestone` field, `watchPoll` polls the milestone filter, and the startup summary reports the route. (#566)

### Changed
- **Supervisor events are a typed envelope with a closed vocabulary**: `supervisor.Event`'s open string vocabulary (doc comment listed eight types; the code emitted thirteen) is replaced at the source: emit sites now publish a typed `Envelope` — timestamp, deployment/job/run identity, closed `EventType` enum (12 audited types), derived `Severity`, human summary, and a structured `Data` slot — and the legacy `Event{Time, Type, Summary, TaskID}` becomes a projection of it (`Envelope.Legacy()`), with `TaskID` existing only in that projection. Foreground stdout renders via `Envelope.ForegroundLine()`, byte-identical to the previous `[HH:MM:SS] type: summary` line (golden test enforces it). Emit sites must use `EventType` constants: a raw string literal at an emit site or an unregistered constant fails grep-style guard tests. One vocabulary defect fixed in the audit: a single emit site said `warn` where every sibling says `warning`. No persistence, no wire exposure, no migration — those follow in M1-18/M1-21 per the Expedition IV store-first contract. (#608)
- **Daemon entry point runs on the shared `Coordinator`**: `runDaemon` in `cmd/deploy.go` hand-assembled its own supervisor, jobs.yaml scheduler, trigger routes, daemon-mode flag, and startup summary — the exact duplication `internal/coordinator` (from #569) was extracted to remove, and which `runForeground` already dropped. It now constructs a single `coordinator.Coordinator` and drives it via `coord.Run(ctx)`, so both entry points host the same spine. Daemon-only behavior is unchanged: crash recovery, the "no jobs found" warnings, the `No jobs to run. Exiting.` early return, dep-graph auto-selection, and the HTTP API wiring (`/status`, `/jobs`, `/jobs/{id}`, `/jobs/{id}/log`) all remain. No schema change. (#582)
- **Agent guidance rewritten for the Opus 5 era**: Every agent contract, both built-in fallbacks, and all seven registry bodies were rewritten to state intent and project-specific facts instead of step-by-step choreography (autopilot's body drops from ~1,050 to ~620 words). Contracts now carry behavior only — project facts belong in `CLAUDE.md`, and scope, human-facing output format, and delegation budget are injected once by `renderHouseStyle` in `internal/supervisor/context.go` so they cannot drift between contracts. Machine-parsed protocol is unchanged: raw `<bail-report>` tags outside any code fence, and the terminal `REVIEW_RISK` line with its `low-risk`/`needs-testing`/`suspect` tiers. (#549)
- **Bailing is now an exception, not a checkpoint**: The old guidance was four independent tripwires ORed together (architecture unclear, unspecified design decisions, untraceable blast radius, unverifiable headlessly) — any one fired a bail, and two of them described a state the agent occupies *before* enough exploration. Replaced with a single test: can you deliver a PR that addresses one distinct problem you understand well enough to move forward on? Each former tripwire now has an explicit way through — read more, narrow the scope to the problem you do understand, decide and document the assumption, or ship and flag what you could not verify. Bail is reserved for having no shippable problem at all, or for work needing human authority (product direction, an intentional breaking change, a migration with undeterminable data implications). Every file-count proxy is gone. (#549)
- **Unverifiable-headlessly changes ship with a note instead of bailing**: autopilot previously bailed when a change needed interactive testing while bug-fixer shipped and flagged — the same situation, two answers. Both now implement, open the PR, and state what a human should smoke test. The reviewer is told to rate those `needs-testing` rather than `suspect`, since declaring an unverified path is correct behavior. Matters disproportionately in this repo, where the TUI, daemon, and external services generate that case constantly. (#549)
- **Partial progress prefers a scoped draft PR over a bail**: when part of an issue stands on its own and passes the gates, agents open a draft PR for it and comment on the issue with what remains, rather than discarding reviewable code in favor of a prose plan. The three-attempt cap on a failing gate stays as a deterministic thrash-guard. (#549)
- **Reviewer and security-scanner no longer suppress findings**: Both contracts told the agent to filter at source (severity floors, "only report if you can trace the taint path"), which current models follow literally and under-report. They now report everything and self-label confidence (`confirmed`/`probable`/`speculative`), leaving triage to the risk tier and the human. The reviewer's three-file edit budget remains as a cap on edits, not on what it reports. (#549)
- **`agents/` collapsed to the one definition that lives nowhere else**: Deleted `agents/{autopilot,reviewer,onboarding}.md`, stale since the v2 rewrite and read by no code — they contradicted the live contracts (a "bail above 8 files" rule the current autopilot explicitly rejects, and an `APPROVE`/`REQUEST_CHANGES` reviewer format nothing parses). One canonical body already serves all three runtimes via `PrepareAgentDef`. `agents/designer.md` remains as a manual-install interactive agent, with `agents/README.md` rewritten to explain the resolution order. (#549)
- **Enroll prompt teaches the new contract shape**: `buildEnrollSystemPrompt` now tells the onboarding agent what belongs in a contract body versus `CLAUDE.md` versus the injected working agreement, forbids verification scaffolding and finding-suppression in generated bodies, caps research fan-out at 4 concurrent sessions, and lists `opencode` among the selectable runtimes. (#549)

### Added
- **Runtime contract documents the I-4/I-5 topology invariants**: Expedition II's topology ADR (`docs/research/fable-expedition/02-worker-process-topology-adr.md` §6) established that a runtime adapter may own process-global shared resources (opencode's shared `opencode serve` process) only because one process hosts exactly one Coordinator driving exactly one deployment (I-4), and that anything needing cross-deployment sharing must be an external service, never a runtime-owned child process (I-5) — both rules lived only in the research doc. `internal/runtime.AgentRuntime` and `runtime.RegisterShutdown` now carry doc comments recording them, so the next runtime-adapter author sees the invariant at the point they'd break it. New `cmd.TestCoordinatorNewCallersAreTopologyOwners` grep-style guard test fails if a `coordinator.New` call site appears outside `runForeground`/`runDaemon`. No behavior change. (#609)
- **Durable per-run/attempt records**: A job can span several stages, retries, and resumed sessions, but only the aggregate `jobs` row and raw logs existed — the read API had no per-run truth. Schema migration v10→v11 adds an `agent_runs` table with one row per `(job_id, stage, attempt)` capturing the agent, runtime, model, session, live `step_count` vs. exact `final_turns`, `cost_usd`, effective limits, `status`/`stop_reason`/`failure_detail`, `final_text`, `log_path`, and `started_at`/`last_activity_at`/`completed_at` timestamps (indexed on `job_id`). `DefaultJobManager` writes a run row at stage start, touches it with live progress as the runtime streams assistant steps, and finalizes it with the terminal outcome — for both code and review stages. New store methods: `StartAgentRun`, `TouchAgentRun`, `CompleteAgentRun`, `GetAgentRuns`, `GetAgentRun`. The table is additive; existing rows are untouched. (#583)
- **Job provenance persisted at activation**: Automation→job navigation inferred a job's origin from its name prefix, which breaks the moment naming changes. Trigger-activated jobs now record their origin durably: schema migration v9→v10 adds nullable `source_type`/`source_name`/`source_ref` columns to `jobs`, `TriggerRoute` carries the automation `Name` (the `jobs.yaml` key), and `createJobForIssue` writes `source_type='trigger'`, `source_name=<automation name>`, and `source_ref=<trigger filter>`. Columns are nullable so existing rows and manually-created jobs stay valid. (#571)
- **opencode shared server reaped on shutdown**: The `internal/runtime/opencode` adapter starts one shared `opencode serve` per process; nothing tore it down, so it leaked after `minder stop` / Ctrl-C until the OS (or reaper) reaped it. Added a registry-level teardown mechanism — `runtime.RegisterShutdown` / `runtime.ShutdownAll` — that the opencode runtime hooks its `Shutdown` into at init. `Supervisor.Stop` calls `ShutdownAll` once in-flight work has drained, staying decoupled from any concrete runtime package; stateless runtimes (`claude-code`, `codex`) register no hook and no-op. Safe when no server was ever started and safe to call more than once. (#557)
- **`CLAUDE.md` drift tests**: `TestClaudeMDSchemaVersion` and `TestClaudeMDBuiltInAgentList` fail when the documented schema version diverges from `db.SchemaVersion()` or the documented built-in agent list diverges from `AgentTemplates()`. Every contract tells agents to read `CLAUDE.md` first, so silent drift there makes agents act on false facts. New exported `db.SchemaVersion()` accessor. (#549)
- **opencode `PrepareAgentDef`**: The `internal/runtime/opencode` adapter now materializes a Minder agent contract into opencode's native on-disk form, writing `<workspace>/.opencode/agent/<name>.md`. Uses the SINGULAR `.opencode/agent/` directory that opencode actually reads (matching `opencode agent create` and the global `~/.config/opencode/agent/` layout); the plural `.opencode/agents/` seen in some docs is a documentation error, noted in a code comment. Idempotent (overwrites on update), no-op on empty workspace, errors on empty name/body. (#537)
- **opencode runtime skeleton**: New `internal/runtime/opencode` package registers the `opencode` runtime so `minder deploy --runtime opencode` passes early validation. `NameOpenCode = "opencode"` added to the runtime registry and blank-imported in `cmd/deploy`. Execution methods are stubs returning `runtime.ErrNotSupported` (or zero values) until the concrete `opencode serve` adapter lands. (#536)
- **Supervisor scenario integration suite**: New `internal/supervisor/scenario_test.go` declares end-to-end pipeline scenarios (`happy-path-pr-opened`, `structured-bail-report`, `max-turns-exhausted`, `permission-denials-warning`) and asserts on the final `jobs` row written by `DefaultJobManager`. New `Makefile` target `make integration` runs the suite (`go test ./internal/supervisor/... -run TestScenarios`). Wired into a `pre-push` lefthook and surfaced as its own `integration-tests` job in CI so failures show up as a distinct check on PRs. (#519)

Unknown runtimes fail early with a clear error, and the selection is propagated through daemon re-exec so foreground and daemon modes stay consistent. ### Fixed
- **`finalizeBail` no longer clobbers structured bail-report fields**: On the bail path, `handleBailReport` writes authoritative `failure_reason="bailed"` / `failure_detail=<reason>` from the `<bail-report>` block, then `finalizeBail` re-runs `ClassifyOutcome`. For clean exits with no `max_turns` / `max_budget` / `is_error` signal the classifier returns `Outcome{}`, and the unconditional follow-up `UpdateJobFailure` was overwriting the bail-report data with empty strings. `finalizeBail` now only writes the classifier output when it produced a non-empty reason, and falls back to `CompleteJob(StatusBailed)` so the status transition still happens. (#517)
- **Goreleaser config for first release**: `.goreleaser.yml` was pointing at the wrong main package (`.` instead of `./cmd/minder`), producing the wrong binary name (`agent-minder` instead of `minder`), and injecting version into a non-existent `main.version` variable so `--version` would always print the dev placeholder regardless of tag. Also removed Windows from the release matrix since `internal/daemon` uses Unix-only `syscall.Setsid`. `cmd.Version` is now a `var` so ldflags can patch it at release time.
- **Picker column display**: `minder checkout` job picker now uses fixed-width columns for label/agent/status/PR and right-aligned full-value cost; the title column expands to fill the detected terminal width so cost no longer truncates to `$1...` and `PR#XXX` lines up consistently across rows. Agent column caps at 9 chars with ellipsis (so a single long agent name no longer pushes every row wide), and a persistent `ISSUE / AGENT / TITLE / STATUS / PR / COST` header now sits above the list (#476)
- **Scheduler SQLite contention and UNIQUE constraint**: Fixed SQLITE_BUSY errors from concurrent scheduler/supervisor DB access; handle UNIQUE constraint violations when reinserting schedules; improved error logging (#431)
- **Daemon exiting on scheduler-only deploys**: Fixed daemon exiting immediately when running with only scheduled jobs and no issue arguments (#427)
- **Enroll validation**: Use minder CLI for YAML validation instead of Python/Ruby YAML parsers (#422)
- **Default review stage**: Add default review stage when agent contract has no stages declared, preventing nil pointer errors (#374)
- **Smart bail extraction**: Handle multi-level JSON escaping in bail report extraction; improved write-to-file pattern for issue comments; fix bail extraction and worktree cleanup across deploy IDs (#408)
- **Stable slot numbering for running jobs**: `RunningJobs()`, `SlotStatus()`, and `StopAgent()` now sort by job ID before assigning slot numbers, preventing nondeterministic ordering from Go map iteration (#384)
- **Git log date parsing fallback**: `Log()`, `LogSince()`, and `LogGrep()` now use `time.Now()` as fallback when commit dates fail RFC3339 parsing, instead of silently producing zero-valued timestamps. Extracted shared `parseLogOutput()` helper to deduplicate parsing logic across all three functions. (#392)
- **Replace custom lastIndex with strings.LastIndex**: Removed custom `lastIndex()` in review.go that reimplemented `strings.LastIndex()` and had a potential panic on short strings (#383)
- **Daemon client HTTP status range check**: Accept all 2xx status codes (not just 200) in `getJSON()` and `post()` methods, so 201/204 responses are no longer treated as errors (#386)
- **Watch filter value validation**: `ParseWatchFilter()` now rejects values containing invalid characters (e.g., semicolons, newlines, slashes). Added comprehensive test coverage for all parse paths. (#387)
- **Distinct error codes in task log endpoint**: `handleTaskLog` now returns `"task_not_found"` when the task ID doesn't exist vs `"log_not_found"` when the task exists but has no log file, instead of a single ambiguous 404 (#388)
- **Daemon heartbeat cleanup on graceful stop**: `StartHeartbeat` stop function now blocks until the heartbeat goroutine fully exits, preventing a race where the heartbeat file could be rewritten after removal during shutdown. Fixes false-positive crash detection on next startup. (#378)
- **Review session uses reviewer agent def and PR context**: The `r` (review session) command now launches Claude with `--agent reviewer` and includes PR body and comments in the initial prompt, matching the automated review path. Previously the session used no agent definition and omitted PR comments. (#348)
- **Max turns fallback detection**: When an agent's stream-json result event is missing (nil result), the supervisor now counts assistant events from the log file to detect turn limit exhaustion. Previously these agents were misclassified as "bailed" instead of "failed" with reason "max_turns". (#340)
- **Autopilot settings display**: Settings panel and autopilot confirm screen now show effective defaults (150 turns, $10.00 budget) instead of raw DB zeros when no override is configured. Bumped default fallbacks from 50→150 turns and $3.00→$10.00. (#341)
- **Worktree preserved until PR merge**: Worktrees for review tasks are no longer deleted immediately when the agent posts a PR. They are now cleaned up only when the task reaches `done` (PR merged), preventing disruption to users with active terminal sessions in the worktree. (#342)

### Changed
- **Long-lived supervisor**: Supervisor stays alive after all tasks complete instead of exiting — both daemon and TUI modes. Watch loop creates supervisor once at startup; new tasks are inserted as `pending` and ingested by the supervisor's 30-second ticker with incremental dep analysis. TUI autopilot mode stays active with idle slots visible until user explicitly presses `A` to stop. Eliminates dual-goroutine dep graph race conditions. (#336)
